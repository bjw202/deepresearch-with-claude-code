01

지식관리의 딜레마

왜 우리의 지식은 사라질까

• 정보는 쏟아지지만, 연결은 끊어져 있다

• 기록은 하지만, 다시 찾지 못한다

• 도구는 많지만, 서로 대화하지 않는다

현재 지식관리의 3가지 병목이 생산성을 저하시킵니다

수집 병목: 이메일, 메신저, 회의록, 문서… 정보는 분산되고 중복된다

검색 병목: "내가 어디에 적었더라?" — 키워드로는 내 의도를 검색할 수 없다

연결 병목: 비슷한 아이디어가 다른 앱에 갇혀 서로 만나지 못한다

Notion, Evernote, 구글 문서, Apple Notes… 도구는 많지만 데이터는 고립되어 있습니다

02

Obsidian

다르게 생각하는 노트 앱

• 로컬 파일 기반 — 당신의 데이터는 당신 것

• 링크 네트워크 — 개별 노트가 아니라 관계가 지식이다

• 플러그인 생태계 — 2,700개 이상의 확장 기능

Obsidian을 특별하게 만드는 3가지 원칙

당신의 데이터는 당신 것

모든 노트는 내 컴퓨터에 .md 파일로 저장. Obsidian을 지워도 노트는 그대로 남는다. 클라우드 종속 없음, 언제든 다른 도구로 이동 가능.

링크가 지식을 만든다

[[다른 노트]]로 연결하면 지식 그래프가 형성된다. 백링크: 누가 이 노트를 링크했는지 자동 추적. 그래프 뷰: 전체 지식 네트워크를 시각화.

플러그인으로 무한 확장

커뮤니티 플러그인 2,700개 이상. Dataview, Templater, Canvas, Bases 등. 도구를 워크플로우에 맞추는 것이지, 반대가 아니다.

Vault는 그냥 폴더입니다. 그것이 핵심입니다.

Vault = 특정 폴더를 통째로 작업공간으로 지정한 것

별도 데이터베이스 없음, 표준 마크다운 파일 집합

VS Code, 메모장으로도 열 수 있다

핵심 기능 요약

기능설명
백링크"이 노트를 누가 링크했는지" 자동 추적
그래프 뷰노트 연결 관계를 네트워크로 시각화
Canvas무한 화이트보드 (노트/이미지/PDF 자유 배치)
Bases (2025)노트를 DB 테이블처럼 보는 공식 기능
CLI (2026)명령줄에서 Obsidian 조작 — 자동화 가능
~/my-vault/ .obsidian/ ← 설정 (숨김) Projects/ ← 프로젝트 Journal/ ← 일일 노트 Resources/ ← 참고 자료
03

AI와의 만남

Obsidian + AI: 왜 찰떡궁합인가

• 파일과 폴더: AI가 바로 읽을 수 있는 구조

• 세 가지 연결 방식: CLI / 플러그인 / MCP

• 실제 워크플로우 사례 4가지

• 경쟁 도구와의 비교

"

Obsidian이 files and folders에 기반하고,
Claude Code도 files and folders에서 동작하기 때문에
둘은 완벽하게 맞물린다

— Nick Milo, Linking Your Thinking (YouTube, 2025, 조회수 10.4만)

클라우드 vs 로컬: AI가 데이터에 접근하는 방식이 다릅니다

BEFORE — Notion

데이터가 Notion 서버에 저장

AI가 접근하려면 API 호출 필요

독점 JSON 포맷 (LLM 친화적이지 않음)

AI 기능이 Business 플랜에 종속 ($20/월)

"AI를 쉽게 쓰는 대신 데이터와 비용을 지불"

AFTER — Obsidian

데이터가 내 컴퓨터에 마크다운 파일로 저장

AI가 파일을 직접 읽고 쓴다 (API 불필요)

마크다운은 LLM이 가장 잘 이해하는 포맷

AI 공급자를 자유롭게 선택 (OpenAI, Anthropic, 로컬 LLM)

"AI를 직접 연결하는 대신 데이터와 제어권을 보유"

컨텍스트 엔지니어링: "AI가 최대한 유용하게 작동하도록 컨텍스트를 설계하는 것"

# Vault Context ## Structure - Projects/ — 진행 중인 프로젝트 - Areas/ — 지속적인 관심 영역 - Resources/ — 참고 자료 - Archive/ — 완료된 것들 ## 지금 하고 있는 일 - [이곳에 오늘의 작업을 적습니다]

실제로 이렇게 활용하고 있습니다: 4가지 사례

일일 노트 + 주간 리뷰

매일 Daily Note → 주말에 Claude Code가 주간 요약. 몇 달 후 시간 사용 패턴 아카이브 완성.

연구 노트 자동 정리

논문→원자 노트 추출→Smart Connections가 연결 제안. PKM Weekly 작성자 200,000단어 집필.

개발자 컨텍스트

Linear → Obsidian → Claude Code. 노트가 쌓일수록 AI가 더 정확해짐 (컨텍스트 복리 효과).

완전 로컬 AI

Copilot + Ollama → 외부 서버 전송 없음. 의사, 변호사 등 기밀 유지 직군에 적합.

Obsidian + AI가 강력한 4가지 구조적 이유

로컬 파일 = AI가 직접 접근: API 없이 파일 시스템을 바로 인덱싱, RAG 최적 환경

마크다운 = LLM 최적 포맷: 헤딩/리스트/코드 블록이 토큰 효율적 인코딩. Notion 독점 JSON보다 LLM 친화적

오픈 생태계 = AI 공급자 자유 선택: OpenAI, Anthropic, 로컬 LLM 중 선택. Notion AI는 모델 선택 불가

프라이버시 = 민감 정보도 AI 활용 가능: 데이터가 내 PC를 떠나지 않음. 의료/법무/연구 기밀에도 적용

에이전틱 PKM이란?

• AI 에이전트가 읽고, 쓰고, 수정할 수 있는 공유 작업 공간
• Obsidian의 로컬 마크다운 vault가 이 역할을 수행
• 클라우드 기반 도구는 API 레이턴시와 비용 때문에 한계

컨텍스트 엔지니어링: 프롬프트 엔지니어링의 다음 단계

더 중요한 질문:

"어떤 AI 기능을 쓸 것인가?"

→ "AI가 최대한 유용하게 작동하도록 vault를 어떻게 설계할 것인가?"

컨텍스트 엔지니어링의 3가지 핵심:

CLAUDE.md: vault의 구조와 규칙을 AI에게 전달

구조화된 프론트매터: YAML 태그, 날짜, 프로젝트 ID로 검색 품질 향상

일관된 폴더 구조: 2~3단계 이내, 너무 깊으면 AI 탐색 비효율적

시작하기 전: 현실적인 한계와 주의점을 알아야 합니다

한계 심각도
학습 곡선 높음
설정 늪 높음
팀 협업 높음
플러그인 리스크 중간
모바일 중간
비용 불확실성 중간

실패 패턴:

CLAUDE.md를 대충 쓰면 AI가 vault를 제대로 이해 못 함

한 번에 모든 것을 자동화하려 하면 실패 — "일일 노트 하나부터"

폴더가 너무 깊으면 AI 탐색 비효율적 — 2~3단계 이내 권장

비용 시나리오:

• Obsidian + Claude API: $20~50/월
• Obsidian + 로컬 LLM: $0 (GPU 투자 별도)
• Notion AI Business: $20/사용자 (고정)
